# ConflictBench 한국어 빠른 시작

Syncthing이 만든 충돌 파일을 비교하고, 사용자가 직접 선택한 결과를 별도 백업과 함께 적용하는 로컬 데스크톱 앱입니다. Syncthing 계정·API 키는 필요하지 않습니다.

## 먼저 데모로 연습하기

압축을 푼 뒤 ConflictBench를 실행하고 **Try demo**를 누르세요. 한글 텍스트, 그림, 바이너리 예제가 표시됩니다. 실제 사용자 파일은 사용하지 않습니다. 데모 폴더와 백업은 앱 종료 시 삭제되므로, 실제 파일 백업용으로 사용하지 마세요.

## 실제 폴더 처리 순서

1. **Open folder**에서 확인할 로컬 동기화 폴더 하나를 고릅니다. 검색 단계는 읽기 전용입니다.
2. 왼쪽 원본 이름 아래의 충돌본을 선택합니다. **Versions**는 두 버전, **Text difference**는 UTF-8 텍스트 차이를 보여줍니다. `-`는 원본에만, `+`는 충돌본에만 있는 줄입니다.
3. 원하는 결정을 선택합니다.
   - **Keep original**: 원본을 유지하고 선택한 충돌본을 외부 백업으로 보관합니다.
   - **Use conflict**: 원본을 선택한 충돌본으로 교체합니다. 이전 두 버전은 외부 백업에 남습니다.
   - **Keep both**: 원본과 확장자가 유지된 별도 이름의 충돌본을 모두 남깁니다.
4. **Review plan**을 누르고 모든 동기화 폴더 밖의 개인용 로컬 백업 폴더를 고릅니다.
5. Syncthing에서 해당 폴더를 일시정지하고 파일을 쓰는 편집기·프로그램을 닫습니다.
6. 계획의 파일 경로·선택·백업 위치를 확인하고 두 확인란을 체크한 뒤 **Save backups and commit**을 누릅니다.
7. 결과를 확인한 다음 동기화를 다시 시작합니다. 여러 충돌본은 하나씩 검토합니다.

## 중단·실패·되돌리기

**History / recovery**에서 이전에 사용한 백업 폴더를 엽니다. 처리 단계와 이력을 확인한 뒤, 동기화·편집기를 멈추고 선택한 기록의 **Undo / recover selected**를 실행합니다. 현재 파일과 백업의 해시가 예상된 상태일 때만 복구합니다. 이후 파일이 바뀌었다면 덮어쓰지 않고 거절합니다. 이 기능은 다른 장치에서 이미 전파되거나 수정된 내용을 되돌려 준다는 뜻이 아닙니다.

## 알아둘 제한

- 여러 파일이 한 번에 원자적으로 바뀌는 것은 아닙니다. 중간 상태가 기록되며 복구 절차를 사용합니다.
- 해시 검증만으로 다른 프로그램과의 모든 경쟁 상태를 막을 수 없으므로 일시정지가 필수입니다.
- 로컬 일반 파일만 지원합니다. 심볼릭 링크, 원본이 없는 충돌, 대소문자 충돌, 네트워크 드라이브, 클라우드 가상 파일은 지원 범위 밖입니다.
- 파일당 256 MiB, 검색 100,000개 항목·1,000개 충돌쌍 제한이 있습니다. UTF-8 텍스트 미리보기 1 MiB, 줄 차이 1,200줄 제한입니다.
- POSIX 기본 권한은 다루지만 ACL·확장 속성·macOS 리소스 포크 보존은 보장하지 않습니다. 백업 폴더는 본인만 접근할 수 있는 곳을 고르세요.
- 외부 비교 도구는 신뢰하는 실행 파일을 직접 고릅니다. 인수는 한 줄에 하나씩 입력하며 `{original}`, `{conflict}`는 검증된 임시 사본으로 치환됩니다. 셸 명령은 실행하지 않습니다.
- 배포 파일은 코드 서명·macOS 공증이 없습니다. 공개된 SHA-256 체크섬을 확인하세요.

문제 보고에 개인 문서나 백업 원문을 첨부하지 마세요. 운영체제, 앱 버전, 민감한 경로를 가린 오류, 재현용 가짜 파일이면 충분합니다.
